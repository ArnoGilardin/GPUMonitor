Tu es un ingénieur principal chargé de diagnostiquer, tester et améliorer une appli appelée “GPU & Server Monitor”.
Objectifs : (1) corriger la connexion (admin/admin en démo), (2) ajouter des tests e2e/UI via App Testing, (3) durcir sécurité/UX, (4) livrer scripts & docs.
Travaille en TypeScript côté API (Node/Express) et React + Vite + Tailwind côté front. DB : SQLite par défaut, option PostgreSQL via DATABASE_URL.

1) Audit & correctifs AUTH

Diagnostiquer la cause du “Invalid username or password” :

Confirmer schéma Users : id, username UNIQUE, password_hash, role, createdAt.

Vérifier hachage (bcrypt ou argon2) et comparaison.

Vérifier seed (admin/admin) réellement inséré en dev.

Confirmer lookup par username (case-insensitive) + timing-safe compare.

Scripts de migration/seed :

npm run db:migrate → crée tables.

npm run db:seed → crée user admin avec mot de passe admin UNIQUEMENT en DEV (contrôlé par NODE_ENV=development + variable ALLOW_DEMO_SEED=true).

Route de bootstrap admin (sécurisée) :

POST /v1/admin/bootstrap active UNIQUEMENT si ALLOW_BOOTSTRAP_ADMIN=true et si aucun admin n’existe.

Paramètres : username, password.

Après création, mettre ALLOW_BOOTSTRAP_ADMIN=false dans la doc.

JWT + refresh :

POST /v1/auth/login → retourne accessToken (short TTL, ex. 15 min) + refreshToken (httpOnly, Secure, SameSite=Lax).

POST /v1/auth/refresh → renouvelle accessToken.

POST /v1/auth/logout → invalide refresh (table de tokens ou rotation).

RBAC simple : rôles admin, viewer. Protéger routes admin (règles/alertes/paramètres).

2) UX/Front Login

Formulaire login :

Indiquer Caps Lock détecté.

Afficher / masquer mot de passe (déjà présent), + bouton “Use demo credentials” en dev qui pré-remplit admin/admin.

Messages d’erreur clairs : “Utilisateur introuvable”, “Mot de passe incorrect”. Éviter de révéler trop de détails en prod (message générique).

Lockout progressif (ex. 5 tentatives → délai 5 min) + rate limit IP/username côté API.

Rappels : “Demo credentials: admin/admin (DEV only)”.

3) Sécurité API

Helmet, CORS (origines autorisées), rate limit (login & /v1/ingest), validation (Zod/Yup) sur toutes les entrées.

Pas de secrets en dur. Fournir .env.example avec :

JWT_SECRET=change_me
REFRESH_SECRET=change_me_too
ALLOW_DEMO_SEED=true
ALLOW_BOOTSTRAP_ADMIN=true
DATABASE_URL= (optionnel pour Postgres)


/health : retourne statut DB, uptime, version.
